# F7Zip

基于 Flutter 与 7-Zip 原生共享库的开源跨平台桌面压缩工具。提供 Windows、macOS、Linux 桌面宿主工程，使用 GitHub Actions 在各自系统上编译和打包。界面沿用桌面压缩软件常见的工具栏、目录导航与文件列表交互。

## 立即运行

完成构建后的应用位于 `dist/F7Zip.app`，可直接双击或复制到应用程序文件夹。

```sh
open dist/F7Zip.app
```

当前构建面向本机 Apple Silicon 架构，最低 macOS 12。应用采用本地签名，尚未经过 Developer ID 签名及 Apple 公证。源码构建时使用当前 Mac 的架构。

## Finder 右键菜单

运行安装脚本将应用放到 `~/Applications/F7Zip.app` 并注册系统服务。

```sh
./scripts/install_macos.sh
```

在 Finder 中选中文件后，右键选择“服务”，使用以下入口。服务菜单的具体层级由 macOS 决定。

- “压缩为 ZIP（F7Zip）”直接在所选项目旁创建 ZIP，不打开主窗口和配置面板。单个项目使用完整文件名，多选使用 `Archive.zip`，重名时自动递增编号。
- “使用 F7Zip 压缩”打开主窗口，配置格式、压缩等级、加密方式和密码，再选择保存位置。
- “解压到当前文件夹（F7Zip）”直接解压到压缩包所在文件夹，不另建同名子文件夹。
- “解压到…（F7Zip）”弹出目录选择窗口，将内容解压到所选文件夹。多选压缩包共用该目标位置。
- 两个解压入口均支持加密压缩包，需要时单独弹出密码窗口，密码错误可重试或取消。已有同名顶层文件或文件夹时整包拒绝解压并提示，保留已有内容。
- “使用 F7Zip 打开”在主窗口浏览压缩包。

如果系统未展示菜单，可在“系统设置 → 键盘 → 键盘快捷键 → 服务 → 文件和文件夹”启用对应 F7Zip 服务。应用升级后重新打开以加载新版本。

## 已实现

- 侧栏和工具栏的“最近打开”、原生“文件 → 最近打开”菜单支持一键清空历史记录，重启后保持清空状态。
- 在新建压缩包中保存、更新、删除及复用压缩预设，记录格式、等级、分卷大小和加密选项。预设行的“重置压缩设置”将本次参数恢复为 ZIP、标准等级、不分卷及默认加密和高级参数，密码保留本次输入。“设置 → 压缩”支持新建、编辑、删除预设及选择默认预设，修改在保存设置后生效，主窗口与 Finder 配置压缩入口自动应用，密码按每次任务输入。
- 创建 ZIP / 7z / TAR / TAR.GZ / TAR.BZ2 / TAR.XZ / GZIP / XZ / BZIP2，选择压缩等级。ZIP / 7z 可设置密码。GZIP / XZ / BZIP2 输入为单个普通文件，TAR 仅打包。ZIP 支持 AES-256（默认）或 ZipCrypto，7z 可选择是否加密文件名。
- 新建压缩包的“高级压缩参数”按格式提供算法、字典、固实块和线程上限，随压缩预设保存并用于 Finder 配置入口。ZIP 可选 Copy / Deflate / Deflate64 / BZip2 / LZMA / PPMd，7z 可选 Copy / LZMA2 / LZMA / PPMd / BZip2。LZMA、LZMA2 和 PPMd 可设置 1–256 MiB 字典，7z 可关闭固实压缩或设置 16 / 64 / 256 / 1024 MiB 固实块。默认沿用原有参数及关闭固实压缩，TAR 仅打包，GZIP 固定 Deflate，XZ 固定 LZMA2，BZIP2 固定 BZip2。线程上限 1–64 或自动，实际并行度由算法和输入决定，GZIP 和 TAR 隐藏线程选项。显示本机逻辑处理器数量和每个编码器的内存粗估，多个编码器会增加总内存，实际字典可能按输入大小缩小。
- “设置 → 解压 → 创建与解压文件名规范化”提供保留原样（默认）、NFC 组合形式和 NFD 分解形式，用于新建归档和解压内容，覆盖 Finder、批量、预览及拖出。创建前检测规范化重名，解压前检测文件与隐含父目录的规范等价拼写，macOS 无法区分的重名在写入前拒绝。转换在私有暂存目录内进行，保留资源叉、权限及目录时间，同步处理相对符号链接和硬链接。规范化创建时，符号链接目标须为归档根目录范围内的相对路径。输出位置使用用户选择的名称。
- ZIP / 7z / TAR 及复合 TAR 使用 AppleDouble 保存、恢复普通文件和目录的扩展属性与资源叉，兼容系统 `ditto` 和 BSD `tar`。恢复普通 rwx 权限，内容回写保留原权限和元数据，重命名、删除及添加替换同步处理关联元数据。
- 安全解压相对符号链接与硬链接，创建 ZIP / 7z / TAR 时保留符号链接。含链接包以只读方式打开。
- 使用 7-Zip 26.06 的完整格式引擎浏览和解压 ZIP、7z、RAR、TAR、GZIP、XZ 等格式。
- 可展开的包内文件树，展示目录和文件，支持空目录、隐式父目录及与右侧列表联动。
- ZIP / 7z 内添加、重名确认替换、递归删除、重命名和新建文件夹，修改前验证版本，校验副本后原子替换。
- “更多操作 → 编辑压缩包 → 更新模式”支持按时间更新、仅更新已有条目和同步目录。选择来源项目后，按当前包内目录及来源名称匹配目标。按时间更新添加新条目并替换较新的来源文件，仅更新已有条目跳过新增文件。ZIP 按 DOS 时间的两秒精度比较，7z 按引擎保存的时间精度比较。同步仅接受实际文件夹，需要确认，以来源内容替换对应同名目录并删除来源中已不存在的条目，保留包内其他目录。外部编辑会话阻止执行，来源文件和目录变化时停止发布，沿用密码、原包备份、副本校验、取消与原子替换保护。
- TAR.GZ / TAR.BZ2 / TAR.XZ 及 TGZ / TBZ / TBZ2 / TXZ 默认直接浏览、选中解压和一步解包，可在“设置 → 解压 → 自动解开 TAR 复合压缩包”关闭，关闭后浏览和解压外层得到 TAR 文件。内层 TAR 在私有临时目录展开，操作结束自动清理。
- ZIP / 7z 可创建数字分卷，提供 10 / 100 / 500 MiB、2 GiB 和自定义整数 MiB（1–2097151）。生成 `.001`、`.002` 等文件，成功后自动打开首卷。已有同名文件或任意数字尾卷时拒绝创建，取消或失败清理本次暂存结果，发布失败回收已发布的本次分卷。请保留整组文件。
- 7z.001、ZIP.001、分卷 ZIP（ZIP / Z01）、RAR 与 RAR5 分卷直接浏览、选中解压和完整性测试，显示卷数并以只读方式打开。数字分卷从 `.001` 打开，RAR 分卷从 `.part1.rar` 打开，缺卷时提示所需文件名。
- 包内目录导航、前进 / 后退、全包搜索、多选、全部解压、选中解压、快速解压到同级目录。
- 按名称、大小、压缩后大小、类型、时间排序，目录优先；属性显示压缩方法、CRC32、加密状态和已有归档注释。
- 紧凑分组工具栏、压缩包信息概览、28 像素行高的多列表格、可拖动宽度的文件树和可切换的目录树显示。
- “更多操作 → 工具 → 校验工具”计算当前归档或所选普通文件的 SHA-256、CRC32、CRC64/XZ，可切换算法复制摘要及路径，支持取消。保存时重新计算并排他发布清单，已有文件受到保护，清单需位于全部文件的共同父目录或其上级目录。支持 GNU 风格 SHA-256 / CRC32 / CRC64/XZ 清单及 SFV 核验，逐项显示一致、摘要不一致、缺失或不可读取。清单上限 4 MiB、10000 项，支持 Unicode、空格、换行、回车和反斜杠文件名；拒绝路径越界和符号链接目标，计算期间文件或目录变化时停止发布。
- “更多操作 → 工具 → 分割普通文件 / 合并分片”按整数 MiB 分割原始字节，生成 `.001`、`.002` 等分片及 `.f7zip-parts.json` 清单。每片大小支持 1–2097151 MiB，最多 10000 片。合并时选择首片或清单，需保留完整的 F7Zip 清单和全部分片，逐片及整体验证 SHA-256，恢复普通 rwx 权限和修改时间。来源始终保留，已有输出受到保护，缺片、额外尾片、错序、损坏、来源变化或取消时清理本次暂存结果。清单上限 4 MiB，空文件生成一片零字节分片。
- “更多操作 → 工具 → 修复 ZIP”扫描小于 4 GiB 的经典单卷 ZIP 本地文件头，支持中央目录缺失、损坏和自解压前缀，重建目录并保存为新 ZIP。每个候选及最终结果由引擎完整校验，加密压缩数据保持原样，需正确密码验证。保留可验证的原压缩数据、本地扩展字段和 DOS 时间，跳过损坏、越界、重复及路径冲突条目并显示原因。单项最多 512 MiB、总恢复量最多 2 GiB、最多 10000 项，扫描最多 100000 个标记，支持经典有签名与无签名数据描述符。ZIP64 暂不支持；仅存于中央目录的注释、权限和链接属性无法恢复，原符号链接内容可能作为普通文件保留。恢复结果仅包含能够找到本地头并通过校验的条目，原包保留。已有输出、源变化、失败及取消沿用排他发布和暂存清理保护。
- “更多操作 → 工具 → 自有归档密码恢复”支持独立单卷 ZIP（ZipCrypto / AES）和 7z（含加密文件名），提供逐行候选词表及自定义字符范围。词表去重、保留有意空格，最多 10000 个 / 4 MiB；字符范围按长度和字符顺序枚举，支持已知前后缀、1–8 字符及最多 1000000 个组合，每个候选最多 4096 UTF-8 字节。单个搜索任务每批最多 8 个候选，可暂停、继续、重新配置，每轮设置 1–3600 秒运行上限。暂停和时限等待当前引擎验证结束，继续时重试未完成的一批。归档上限 512 MiB / 10000 项，总展开大小最多 256 MiB，最小加密条目最多 64 MiB；源变化时停止，原包只读。找到密码后验证一个加密文件条目，结果默认隐藏，可显示或复制；不同文件使用不同密码的归档需逐项处理。损坏也可能造成全部候选失败。搜索配置和进度仅保留在窗口内，关闭后清除，候选与结果不写入配置或搜索日志。
- 新建压缩包和预设支持 ZIPX 与 WIM。ZIPX 使用 ZIP 容器，默认 LZMA，可选 BZip2、PPMd 或仅存储，沿用字典、线程、AES / ZipCrypto 和数字分卷。采用高级算法时，读取端需支持相应 ZIP 方法。WIM 使用 7-Zip 26.06 创建器支持的存储方式，等级固定为 0，提供单映像数据归档、多文件和目录，不支持密码、分卷或创建压缩 WIM；浏览和解压为只读。两种格式沿用 Unicode 规范化、macOS 元数据、已有输出与取消保护。ZIPX 的 LZMA / BZip2 已由 Python zipfile 独立解码，两种格式均与官方独立 7zz 26.06 完成双向测试及内容核对。可运行 `python3 test/extra_formats_cross_tool.py --sevenzip /path/to/7zz` 复验。
- 属性展示 ZIP 与旧 RAR 的逐文件注释，以及 ZIP / RAR 的可用归档注释。“更多操作”可编辑 ZIP 文件和归档注释，支持清空，每次最多 16384 UTF-8 字节，沿用原包备份、版本、密码及取消保护，发布前验证条目、CRC 和加密状态。添加替换、重命名、时间更新和外部编辑回写保留逐文件注释。旧 RAR 注释复用现有解码器并校验 CRC，优先读取有效 UTF-8，未标记旧编码使用 CP437，服务块支持 UTF-16，RAR 归档注释上限 256 KiB；损坏或未支持的注释会显示不可用。RAR 注释以只读方式展示。另补齐原生路径和注释中的非 BMP 字符，支持表情文件名往返。
- 完整性测试、实时进度、后台任务和取消。
- 文件名区域支持拖出到 Finder，目录与多选通过 macOS 文件承诺在落点确定后串行解压。父子选择去重，同名项目由 Finder 处理，源归档或分卷变化时停止，支持密码重试和取消，已有目标受到排他发布保护。单独拖出符号链接时需选择包含目标的目录。
- 工具栏、右键菜单或“View → 内置预览”可在应用内查看图片、文本、PDF、常见音频和 MP4 / MOV / M4V。文本上限 4 MiB，其他类型上限 256 MiB，同时最多两个窗口。解包中间层也受预算约束。图片限制为单帧 4000 万像素、总计 8000 万像素、最多 512 帧及边长 16384，PDF 最多 1000 页。关闭、失败、取消和正常退出时清理私有暂存目录，预览密码仅保留在内存。
- 包内 ZIP、7z、RAR、TAR 及常用流格式可直接进入子包，也可从右键或“View → 进入子压缩包”打开。导航栏和原生菜单提供“返回父压缩包”，返回时重新读取父包并恢复目录、搜索和选择。子包为只读，可解压、预览和拖出，每层暂存上限 256 MiB、最多八层，每层独立处理密码，并在当前会话中复用已验证密码。包内分卷需先整体解压后打开。返回、关闭归档、切换外部归档、失败、取消及正常退出清理子包暂存；子包快速解压会要求选择保存目录。
- 工具栏“任务队列”或原生“文件”菜单可批量选择压缩包，依次解压到指定目录或执行完整性测试。每项显示阶段、进度、当前文件、错误与结果，等待项和执行项可独立取消，失败和取消项可单独重试。Finder 的打开、压缩与解压请求使用同一队列，多包解压共享一次目标目录选择。普通任务失败后继续后续任务，已结束的最近 100 项记录与队列保存在当前会话内，重试按需重新输入密码。
- 新建加密压缩包支持随机密码生成，可调整 8–128 位长度、大小写字母、数字、特殊字符并排除易混淆字符。成功创建后自动将压缩包路径、密码和创建时间保存到本机系统安全存储。“设置 → 密码 → 压缩包密码历史”或随机密码生成器中的“压缩包密码历史”可查看、复制密码、定位压缩包和逐条删除记录。密码默认隐藏，历史独立保留每次创建记录，压缩包移动后仍记录原路径。历史保存失败会提示用户自行保管密码。
- “设置 → 密码”可在本机默认 macOS Keychain 新增、更新和删除最多 20 个常用密码。自动尝试默认关闭，开启后用于打开、解压、测试、预览、拖出、嵌套归档及编辑回写；候选失败或钥匙串不可用时继续手动输入。每个密码上限 4096 UTF-8 字节，已使用密码在当前会话中复用。配置与编辑恢复清单保存授权及恢复信息，密码值由钥匙串管理。密码条目操作即时生效，自动尝试开关通过“保存设置”生效。
- 拖入压缩包打开，拖入普通文件或文件夹创建压缩包，已有可编辑包打开时添加到当前目录。
- Finder 右键“服务”菜单提供快捷 ZIP、配置压缩、原地解压、选择目录解压和打开，支持冷启动、密码重试和请求排队。
- 通过 Finder 的“打开方式”打开压缩包，以及在 Finder 显示处理结果。
- 可配置的隔行背景、单击 / 双击打开，以及 `..` 导航项。
- 可配置查看和编辑程序，ZIP / 7z 内文件在外部程序保存后自动回写。
- 后缀默认程序关联与恢复先前应用。
- 原生文件菜单及持久化最近文件列表（最多 8 项）。`⌘O` 打开、`⌘N` 新建、`⌘E` 解压、`⇧⌘A` 添加、`⇧⌘N` 新建文件夹、`⌘I` 属性、`⌘⌫` 删除、`F2` 重命名、`F3` 查看、`F4` 编辑、`⌘[` / `⌘]` 后退 / 前进、`⌘,` 设置，在文件列表中按 `⌘A` 全选。

数字分卷会在私有临时目录拼接完整内层归档，需预留对应磁盘空间，操作完成或失败后自动清理。读取、测试和解压会核对同组全部分卷的文件版本，检测期间发生变化时停止发布结果。

主窗口内的解压默认使用以压缩包命名的目标文件夹，同名文件夹可复用。目标名称被普通文件等其他项目占用时递增编号。任务使用私有暂存目录，失败和取消时清理暂存内容。主窗口和 Finder 解压遇到冲突时可选择跳过同名文件、自动改名、合并目录或替换同名普通文件。替换需再次确认，目标中的符号链接与文件夹不会作为普通文件被替换，原压缩包及其分卷受保护。确认期间目标变化会停止操作，发布失败或取消会回滚本次新增和替换；外部修改阻挡回滚时保留暂存目录并提示恢复路径。选择压缩包保存位置时，已有归档仍需改用新文件名。

“更多操作 → 解压 → 解压后移至废纸篓”提供需确认的一次性操作，完整解压成功后核对源版本，再调用 macOS 废纸篓。选中解压、跳过同名文件、分卷和嵌套临时包保留源文件，外部编辑中的归档需先结束监控。回收失败时保留解压结果并恢复源包，恢复位置被并发文件占用时，将源包保存在私有目录并提示路径。成功回收后关闭当前归档，可在 Finder 废纸篓中取回源文件。

“设置 → 解压 → 智能选择解压目录”默认关闭并记住选择。开启后，主窗口与 Finder 选择目录解压根据暂存结果判断目标。单个文件或单个目录直接落在所选父目录下，多个顶层项目使用归档名文件夹，空归档也使用归档名文件夹。选中解压只按选中结果判断，AppleDouble 元数据恢复后参与判断。同名项目沿用冲突处理，自动改名后“查看结果”定位实际文件。Finder 的“原地解压”直接使用归档同级目录。

“设置 → 解压”提供“解压时删除冗余的根目录”选项，默认关闭并记住选择。开启后，主窗口（含选中解压、快速解压）和 Finder 解压在结果只有一个顶层文件夹时去掉这一层，保留其内部目录结构。存在多个顶层项目或顶层为文件时保持原结构。处理在暂存目录内完成，仍保留同名冲突保护。智能解压启用时，先按此设置剥离根目录，再判断单文件、单目录或多个顶层项目。

为避免递归压缩，压缩包需要保存到所选输入文件夹之外。解压拒绝越界路径、绝对链接、循环链接，以及设备、管道和套接字条目。符号链接需要可用的包内目标，选中解压时请同时选择目标文件；硬链接会自动补齐其普通文件数据依赖。自动改名会调整符号链接引用，去掉根目录会改变链接边界时保留这一层。含链接包的编辑暂未开放。

文件保真覆盖普通文件和目录的 rwx 权限、扩展属性与资源叉，忽略 setuid/setgid 等特殊权限位。GZIP / XZ / BZIP2 单文件流不携带 AppleDouble 元数据，需要保留这些属性时可选择 ZIP、7z 或 TAR 系列。系统来源跟踪属性 `com.apple.provenance` 不会单独触发元数据条目生成。

## 浏览设置与文件关联

主窗口顶栏按平台布局。macOS 左侧使用红黄绿按钮，分别关闭、最小化和切换全屏。Windows、Linux 右侧使用最小化、最大化／还原和关闭按钮，通过 `window_manager` 同步窗口状态。拖动顶栏留白移动窗口，macOS 双击遵循系统标题栏操作设置，Windows、Linux 双击切换最大化。工具栏采用紧凑横排，窄窗口中的查看、编辑等操作可在“更多操作”找到。

Windows、Linux 使用共享桌面接口实现系统文件面板、设置持久化、外部程序打开、文件关联、密码安全存储、主题选色、预览和拖出。macOS 使用 Swift 原生接口。Windows、Linux 的键盘快捷键使用 Ctrl。

点击右上角齿轮或按 `⌘,` 打开设置。设置按常规、主题、压缩、解压、文件关联、外部程序和密码分为七页。“主题”页中的外观支持跟随系统（默认）、浅色和深色，保存后立即生效并随重启保留。切换主题同步 macOS 窗口和系统文件面板外观，跟随系统时响应系统外观变化。配色使用 Material 3 的 `ColorScheme.fromSeed`，侧栏、导航、表头、列表及状态区使用对应语义色。“主题”页中可选择经典紫（默认）、森林绿、青绿色、玫瑰粉、暖橙色和海洋蓝六组颜色主题，与明暗模式独立配置。选择时在设置窗口内预览，保存后全局生效并随重启保留，取消则保留原配色。欢迎页提供打开、新建及拖放提示，搜索支持一键清除。默认启用隔行背景、单击打开和 `..` 目录项，可在“常规”中切换，设置随应用重启保留。

“自定义主题…”支持输入主题名称和 `#RRGGBB` 种子色，也可通过“调色盘…”使用 macOS 原生色轮、滑块及颜色样本选色。浅色与深色预览同时展示按钮、文件夹及文件选中效果，随调色盘选色实时变化，取消选色恢复原色。可保存多组主题并编辑、删除。“导出当前主题…”将当前内置或自定义主题导出为 JSON，“导入主题…”读取该文件并选中导入主题，同名主题自动添加编号。新增、编辑、删除与导入通过“保存设置”持久化，取消设置会放弃这些修改。主题文件采用 `f7zip-theme` 格式、版本 `1`，包含 `theme.name` 和 `theme.seedColor`，文件上限 64 KiB。

“设置 → 解压 → ZIP 文件名编码”支持自动检测、UTF-8、GB18030、Windows CP936 / GBK、Big5、Shift-JIS、CP949、Windows-1252 和 CP437。自动检测使用 macOS 的编码识别，短文件名或混合编码出现歧义时可手动选择。ZIP 的 UTF-8 标记及有效 Unicode 扩展信息优先。保存后刷新当前归档的文件树，查看、解压与编辑使用一致的编码。正在外部编辑的归档保留会话编码，切换到不同编码前需结束监控。旧编辑会话缺少编码字段时使用自动检测。

新建 ZIP / ZIPX 的文件名显式使用 UTF-8，非 ASCII 名称在本地文件头及中央目录写入 UTF-8 标志，覆盖主窗口、Finder 和压缩预设入口。创建窗口显示编码策略。“ZIP 文件名编码”用于读取旧归档，创建策略始终使用 UTF-8。Windows 旧程序使用的本地代码页随地区变化，简体中文常见 CP936 / GBK、日文常见 CP932，未写入编码标识的旧 ZIP 可能需要手动指定来源代码页。发送方使用明确标记 UTF-8 的 ZIP，接收方使用支持 UTF-8 的解压软件，可以保留中文、日文、韩文和 emoji 等跨语言名称。编码检测对缺少标识的短文件名、混合代码页及创建时已经损坏的文件名有局限。[Windows 代码页说明](https://learn.microsoft.com/en-us/windows/win32/intl/code-page-identifiers) · [ZIP 格式规范](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)

文件列表中的勾选框用于多选。单击模式下点击文件名会打开文件，点击文件夹会进入目录。关闭单击模式后使用双击打开。仅在压缩包子目录显示 `..`，激活后返回包内上一级目录，根目录隐藏此项。导航项不参与全选和解压选择。

在“文件关联”中按后缀点击“设为 F7Zip”。支持 ZIP、7z、RAR、TAR、GZ、XZ、BZ2、ISO、TGZ、TBZ、TBZ2、TXZ、001、Z01、R00、ZST、CAB、DMG、WIM、JAR、APK。macOS 会按需要要求确认。成功关联后可通过“恢复原应用”恢复此前的默认程序。

## 外部查看与编辑回写

ZIP / 7z 的添加、删除、重命名、新建文件夹和编辑回写会在替换原包前保存完整备份。备份位于原包同级的 `<原包名>.f7zip-backup-XXXXXX` 私有目录中，包含 `original.zip` 或 `original.7z`，保留原文件属性和加密内容。备份失败时停止修改。通过“更多操作 → 编辑压缩包 → 恢复原包备份”选择完整版本并确认恢复，恢复前同样备份当前版本。恢复会替换整个归档，需先结束该包的全部外部编辑监控。版本变化、损坏备份、错误密码或取消会停止恢复。备份按原包名称和位置查找，移动或重命名原包后可在 Finder 中取回原备份文件。备份持续占用磁盘空间，可在 Finder 中手动清理。

在设置的“外部程序”页选择查看程序和编辑程序，支持 macOS `.app`，留空时使用系统默认程序。

- 单击或双击文件、工具栏“查看”和文件右键菜单均可打开查看程序。
- 勾选一个文件后点击“编辑”，或右键选择“编辑并自动回写”。
- 在编辑程序中保存当前文件，内容稳定后会自动更新对应 ZIP / 7z，并刷新列表。
- 底部“管理编辑文件”可定位工作文件、重试回写或结束监控。关闭管理窗口后继续自动回写。结束监控会保留工作文件。

编辑工作文件和恢复清单保存在 `~/Library/Application Support/F7Zip/EditSessions`。重启应用会恢复编辑会话。恢复加密会话时按常用密码授权尝试，或通过“重试回写”输入密码。查看文件使用系统临时目录。

本应用添加和其他结构修改会接续未受影响编辑会话的版本。正在外部编辑的目标禁止被删除、重命名或替换。

回写会先锁定并验证原包、更新副本、校验结果，再原子替换。保留加密状态、原包其他条目、权限及扩展属性。原包被外部修改或发生写入错误时，应用保留工作文件并提示处理。

## 构建

需要 Flutter 3.47.9（Dart 3.13.7）、Python 3.9+、Git 和目标平台工具链。在目标系统运行统一构建入口。

```sh
python3 scripts/build_desktop.py
```

| 目标平台 | 构建环境 | 发布产物 |
| --- | --- | --- |
| Windows x64 | Windows、Visual Studio C++ 桌面工具、MSYS2 UCRT64 | `dist/F7Zip-windows-x64.zip` |
| macOS | macOS、Xcode、CocoaPods | `dist/F7Zip-macos-<架构>.zip` |
| Linux x64 | Ubuntu 22.04+、GCC、Clang、CMake、Ninja、GTK 3 开发库 | `dist/F7Zip-linux-x64.tar.gz` |

Windows 原生构建在 MSYS2 UCRT64 终端运行，需要 `make`、`git` 和 UCRT64 的 GCC、Clang、Python、pkgconf、ICU、nlohmann-json。打包脚本递归收集原生 DLL 依赖，应用使用 Windows UTF-8 和长路径清单。Windows 的已有默认应用由系统管理，文件关联操作会按需要打开系统默认应用设置。

Linux 构建依赖安装命令如下。

```sh
sudo apt-get install clang g++ cmake ninja-build pkg-config libgtk-3-dev libsecret-1-dev libicu-dev nlohmann-json3-dev libmpv-dev libasound2-dev xdg-utils shared-mime-info
```

Linux 运行环境需要 GTK 3、ICU、Secret Service（例如 GNOME Keyring）和 libmpv。Linux 按 MIME 类型关联，同一类型的后缀共享默认程序。Windows 密码使用系统安全存储，Linux 使用 Secret Service。Windows、Linux 预览通过 Flutter 对话框展示，拖出先在私有临时目录准备内容，退出时清理。Windows 创建符号链接需要目标系统提供相应权限。

macOS 也可继续使用 `./scripts/build_macos.sh`，产物位于 `dist/F7Zip.app`。该脚本执行本地签名。

首次构建自动下载并校验固定版本的 7-Zip 26.06 和 bit7z 4.0.10 源码。桥接库按平台生成 `f7zip.dll`、`libf7zip.dylib` 或 `libf7zip.so`，随应用嵌入。Windows 引擎为 `7z.dll`，macOS、Linux 引擎为 `7z.so`。Windows、Linux 复用 7-Zip 自带的 SHA-256 实现，并通过 ICU 处理 Unicode 和旧编码检测。

开发运行前先编译原生库。

```sh
python3 scripts/build_native.py
flutter pub get
flutter run -d macos
```

Windows、Linux 开发运行时将最后一条命令的设备改为 `windows`、`linux`。Release 构建同时生成 `dist/F7Zip-sources.tar.gz`，包含自有代码和原始 7-Zip、bit7z 源码。

### GitHub Actions

工作流位于 `.github/workflows/desktop.yml`。向 `main`、`master` 或 `codex/**` 分支推送、提交 Pull Request，或手动执行工作流，均会启动 Windows、macOS、Linux 构建。构建任务执行静态检查、真实原生归档回归及平台打包，macOS 还执行完整 Python 和 Flutter 测试。

构建通过后，从 Actions 页的 Artifacts 下载对应平台包。推送 `v*` 标签会在三平台全部通过后创建 GitHub Release，并上传发布包及对应源码包。包内保留原生引擎依赖与第三方许可证。

## 命令行

Release 应用提供 `dist/F7Zip.app/Contents/MacOS/f7zip-cli`，开发构建提供 `native/lib/f7zip`。可从任意工作目录调用，符号链接入口会解析实际程序位置并加载同一份原生引擎。

```sh
cli="$PWD/dist/F7Zip.app/Contents/MacOS/f7zip-cli"
"$cli" --help
"$cli" open ./sample.zip
"$cli" compress --format 7z --level 5 ./output.7z -- ./input
"$cli" extract --quiet ./sample.zip ./output
"$cli" test --quiet ./sample.zip
printf '%s\n' "$ARCHIVE_PASSWORD" | "$cli" test --quiet --password-stdin ./encrypted.7z
```

压缩可指定格式、等级、算法、字典、线程、固实块、分卷及加密方式，默认按输出扩展名选择格式，无扩展名时使用 ZIP。ZIP 密码默认 AES-256，`--zipcrypto` 选择兼容方式；7z 默认加密文件名，`--visible-names` 保留可见名称。创建和解压支持 `--normalization preserve|nfc|nfd`，解压可用 `--remove-root` 去掉冗余根目录。`--encoding` 为读取 ZIP 时的编码页编号。参数详情见 `--help`。

stdout 为一行 JSON 结果，stderr 为逐行 JSON 进度，`--quiet` 隐藏进度。密码使用 `--password-stdin` 读取至 EOF，去掉末尾一个 LF，最多 4096 UTF-8 字节。以 `--` 开头的路径放在参数分隔符 `--` 后。压缩和解压沿用暂存、已有文件保护及失败清理，SIGINT / SIGTERM 请求取消并清理本次结果，失败后可使用同一路径重试。

| 退出状态 | 含义 |
| --- | --- |
| 0 | 成功，`open` 表示 macOS 已接受打开请求 |
| 1 | 引擎或系统操作失败 |
| 2 | 参数错误 |
| 3 | 需要正确的归档密码 |
| 130 / 143 | SIGINT / SIGTERM 取消 |

功能差距、优先级与推进记录见 [功能任务清单](TASKS.md)。

可复现的原生压缩、解压及 ZIP 并行实验见 [性能基准](benchmarks/README.md)。

## Windows 自解压包

新建压缩包的格式选择提供“Windows 自解压 EXE · x86”，默认使用 LZMA2，可选择 LZMA、PPMd 或仅存储，支持字典、线程、固实块、AES 密码和文件名加密。预设和 CLI 复用这些选项，创建单个 EXE。模块固定为官方 7-Zip 26.06 普通 GUI 解压器，PE 架构为 x86，可用于支持 32 位程序的 Windows x64 环境。构建和每次创建均核对模块摘要，打包后再测试内层归档，验证通过后排他发布。来源、已有输出和运行中取消沿用保护，检测到来源变化时停止发布。

普通模块在解压完成后结束。生成的 EXE 未签名，包内文件的可信度取决于其来源，Windows 安全软件、SmartScreen 或企业策略可能提示或阻止运行。创建时保守检查 Windows 文件名、设备名、大小写及规范等价冲突，符号链接来源会被拒绝。输出面向 Windows，macOS 可将其作为归档读取。

通过“打开”、拖入文件、Finder 服务或包内嵌套入口读取带 MZ 前缀的 7z、ZIP、RAR / RAR5 单卷 SFX，支持前缀不超过 16 MiB 的归档。浏览、测试、选中解压、预览和拖出使用内层归档数据，SFX 以只读方式浏览。打开归档全程通过归档引擎解析和提取数据。

```sh
native/lib/f7zip compress --format sfx output.exe -- ./input
native/lib/f7zip test --quiet output.exe
native/lib/f7zip extract --quiet output.exe ./output
```

当前验证覆盖 macOS 上的创建、载荷校验和归档式读取，并以官方独立 7zz 验证算法与非 BMP Unicode 密码的双向兼容。Windows GUI 实际执行、长路径、目标系统策略及签名交付尚待 Windows 环境验收。可运行 `python3 test/sfx_cross_tool.py --sevenzip /path/to/7zz` 复验数据兼容性。[模块来源与摘要](native/sfx/README.md)
