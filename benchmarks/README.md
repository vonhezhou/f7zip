# 原生性能基准

在项目根目录运行以下命令。先构建原生库，测试期间保持机器空闲。

```sh
python3 scripts/build_native.py
python3 scripts/benchmark_native.py --size-mib 16 --repetitions 3 --workers 4 --output /tmp/f7zip-benchmark.json
```

脚本使用 Python 3.9+ 标准库。全部工作文件放在临时目录，结束后回收。语料固定种子为 20261110，文件时间固定，报告记录文件摘要集合、二进制 SHA-256、平台、处理器数量、每次墙钟耗时及中位数。计时覆盖完整 CLI 进程、引擎、元数据和排他发布。语料生成、结果 SHA-256 验证及清理在计时之外，结果验证失败会终止基准。

这是热缓存测试，未清理系统文件缓存。不同机器、系统负载、存储和电源状态会影响结果。`--size-mib` 仅影响 mixed 和 single，tiny 固定一个 32 字节文件，small 固定 256 个 4 KiB 文件。mixed 包含 32 个文件，交替为可压缩文本和固定伪随机字节。single 为一个可压缩文件。ZIP / 7z 均使用当前默认等级 5 和自动线程设置。

## 2026-11-10 测量

环境为 macOS 27.2 arm64，18 个逻辑处理器，mixed / single 为 16 MiB，每种情况三次。完整原始数据见 [优化前](native-before.json) 和 [优化后](native-after.json)。优化前 CLI 每次完成后仍等待 100 毫秒轮询，优化后由条件变量立即唤醒。信号取消和进度仍以最多 100 毫秒的间隔轮询。

| 语料与格式 | 压缩前 / 后，毫秒 | 解压前 / 后，毫秒 |
| --- | --- | --- |
| tiny ZIP | 122.4 / 9.0 | 121.9 / 6.0 |
| tiny 7z | 122.0 / 6.2 | 118.9 / 5.4 |
| small ZIP | 450.5 / 355.5 | 115.3 / 100.5 |
| small 7z | 115.2 / 103.4 | 114.9 / 85.8 |
| mixed ZIP | 4797.0 / 4684.2 | 770.9 / 694.2 |
| mixed 7z | 1426.8 / 1374.4 | 228.0 / 118.2 |
| single ZIP | 1540.5 / 1488.5 | 117.5 / 23.2 |
| single 7z | 1442.5 / 1369.2 | 120.1 / 15.3 |

## ZIP 并行解压评估

7-Zip 26.06 的 `CPP/7zip/Archive/Zip/ZipHandler.cpp` 中 `CHandler::Extract` 逐项循环，`SetNumberOfThreads` 传给单个解码器。普通 Deflate ZIP 的条目级并行需由调用方调度多个独立 reader。

脚本另行比较一与四个独立 C ABI reader。每个 worker 选取互斥条目，写入独立私有目标，全部完成后在计时之外聚合并核对 SHA-256。此实验省去 CLI 启动耗时，计入线程池创建、每个 reader 的完整目录读取、路径检查、来源版本核对与各自发布。实验只覆盖无链接的普通文件，生产的共享目标、跨条目链接、元数据及取消回滚仍需协调。

small 单路 / 四路为 96.0 / 228.2 毫秒，mixed 为 684.8 / 1445.0 毫秒。四路实验均慢于单路，重复读取与检查占据较大开销。因此当前保留顺序解压。可用相同脚本扩大语料继续评估，现有结果不足以支持把并行调度接入生产解压路径。
